# 単語対戦

フレンド欄の「単語対戦」から全画面で一人プレイ、部屋作成、6桁の部屋番号による参加ができます。部屋の待機期限は2分、参加後は3秒のカウントダウンと60秒の試合です。ホストが選んだ単語帳全体から異なる意味を持つ最大120語を端末内で抽選し、両者に同じ問題順を出します。意味は先頭の意味を使用します。問題の単語は一巡するまで重複を避け、選択肢を順に入れ替えます。10語程度の小さな単語帳では選択肢の重複は避けられません。問題ごとの単語帳読み込みはありません。

9択と「選択肢の中にはない」の10択です。正解は100→110→120…点、ミスは−50点とコンボ解除。一人プレイの結果はレートや理解度に加算しません。対戦はElo（初期1500、K=32）、同点は引き分けです。退出・アプリ非表示は途中退出として扱います。

レートはヘッダーの時計右、ユーザー詳細、ランキングの「対戦レート」に表示します。対戦中は勉強時間の計測対象です。

プレイヤーのアイコンと装備中のフレームを表示します。アイコンは取得済みのユーザー一覧を優先し、必要な場合のみ相手のプロフィールを1回読みます。画像を部屋の更新データには含めず、キャッシュは最大4人・5分です。コンボの短い演出と残り時間のバーを追加し、動きを減らす設定も尊重します。ミス時は選択肢の正解と正しい意味を表示し、次へ進むまで回答を無効にします。確認中も時間は進みます。

## シングルプレイのベスト

60秒完走時のみ自己ベストを保存します。途中終了・アプリ非表示は対象外です。単語帳共通のスコアランキングです。0点・負のスコアも完走記録として扱い、未プレイと区別します。

端末の `core_v4_word_duel_solo_{ID}` に記録と未同期フラグを保存し、IndexedDBにもミラーします。ログイン中はユーザードキュメントの `wordDuelSoloBest`、`wordDuelSoloBook`、`wordDuelSoloBestAt` のみをトランザクションで更新します。小さい記録では書き込まず、クラウドの大きい記録は保持します。失敗時は未同期フラグを残し、起動・オンライン復帰・画面復帰時に再試行します。ゲストは端末内のみです。レートや理解度は変更しません。

ランキングの「シングル」に表彰台を追加します。既存のユーザー一覧取得に同じフィールドを含めるため、ランキング切り替えのための追加コレクション取得はありません。

## 通信と保存

既存のFirestoreで `wordDuelRooms/{6桁番号}` を作成します。出題方式を変更したため部屋の形式はversion 2です。旧版の部屋とは接続できず、両者とも最新版に更新して作り直す必要があります。監視は参加中の1部屋だけです。回答は250msの待機と通信中のまとめ送りで同期し、終了時に最終回答を送ります。部屋を閉じる・試合終了で監視とタイマーを停止します。部屋一覧を定期取得しません。ただし対戦中は回答同期に伴う読み取り・書き込みが増えます。

試合結果と両者の `users/{ID}` の `wordDuelRating`、`wordDuelGames` を同じトランザクションで確定し、確定済み試合の再集計を防ぎます。理解度・単語帳・ワーク・既存の学習カウンターは書き換えません。通信失敗時は結果を再確認するボタンを表示し、成功扱いにはしません。

通信断や強制終了の退出送信は保証できません。終了時刻から7秒後にも終了記録がない参加者は途中退出として集計します。端末時計を使用するため時計のずれの影響があります。終了済み部屋の自動削除は未設定です。

## 検証と本番での制約

Chromium・WebKitの2画面で全画面表示（393px・320px）、フレーム付きアイコン、ミス時の正解表示と回答無効化、ベストスコアの同期・ランキング、途中終了・低スコア時の記録維持を確認しました。同一問題、相手スコア更新、60秒終了、コンボと減点、Elo更新、二重集計防止、既存学習フィールドの維持も確認しています。保存容量エラー・再起動・アカウント変更・同期待ち中の新記録もテストしています。ブラウザーテストは共有メモリー上のFirestore代替を使用し、本番Firestoreへの書き込みは行っていません。

本番の新規部屋パスへの読み取り接続は確認しましたが、部屋作成・監視・両者のレート更新の権限は未検証です。Firebase設定やセキュリティルールは変更していません。既存ルールで許可されなければオンライン対戦は接続エラーになります。一人プレイには部屋へのアクセスは必要ありません。

今回の計算・集計はブラウザー内です。回答ログからスコアを再計算し入力形式を検証しますが、改変されたクライアントによる不正を防ぐサーバー認証にはなりません。公開競技として運用する場合は、認証されたユーザーとサーバー側の回答検証・結果確定が必要です。全ユーザーへの書き込みを無条件に許可するルールは追加しないでください。
