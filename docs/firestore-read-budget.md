# Firestoreの読み取り削減と上限時の扱い

Firestoreの読み取りは画面を開いた回数ではなく、主に取得したドキュメントの件数で数える。一覧の全件取得・トランザクション内の参照・管理コンソールでの閲覧も使用量に影響する。画像のバイト数を減らすだけではドキュメント読取回数は減らない。

確認した主な不要処理は fix.js の旧管理者リセット世代ポーリング。コメントは60秒だが、実際のsetIntervalは900msで、接続中なら1人1時間に約4,000回のshared/app_settings取得を要求し得た。廃止済みの管理機能なので定期取得を削除する。起動時の既存チェックと学習データ保存は変更しない。

ランキング一覧の自動更新は5分ごとにし、5分以内のタブ切替・画面復帰は取得済み結果を再利用する。手動更新は可能。ランキングと勉強時間の内容が前回成功時から変わらなければ同期トランザクションを省略する。失敗した変更は成功済みとして扱わず、次回の同期に残す。

SDKのドキュメント取得・一覧取得・トランザクションでresource-exhausted／quota exceeded／429を受けた時は5分間新しい読取を抑制する。上限解除を確認するため、時間経過後は再試行可能。取得失敗はエラーとして返し、空のSnapshotを作らない。これにより既存の端末保存・表示済み結果を維持するエラー処理を使う。課金プラン、Firebase設定・実データは変更しない。

無料枠は通常1日50,000読取・20,000書込で、日次枠は米国太平洋時間の午前0時にリセットされる。無料プランで超過するとクラウドの取得・同期などが失敗し得る。共有一覧や新しい端末での初回読込まで常に動作する保証はない。保存済みデータを消さず、不要な再試行を抑える対応である。

公式資料: https://firebase.google.com/docs/firestore/quotas

検証: 変更なしの同期省略・変更時の同期・旧監視の反復取得停止・上限時のバックオフ・ローカルのランキング値とプロフィール画面の保持をChromiumとWebKitで確認。実プロジェクトの請求画面・実際の上限到達は操作していない。使用量の減少はマージ・配信後に確認する。

## 表示中のランキングだけを取得

「学習」と「単語バトル」を分けて初回取得し、各グループで5分間キャッシュする。対戦レートでは上位3人の表彰台と、4位以下がいる場合のみ展開できる一覧を表示する。表示していないグループを先読みしない。タブ移動・グループ切替で進行中のfetchを中止し、15秒の期限を設ける。時間がかかる初回読み込み・手動更新では既存のロードクイズを表示する。

Firestore RESTのrunQueryを利用し、20件ごとに必要なフィールドだけをselectする。対戦ではレート、学習ではrankingLearningSummaryV1と表示に必要なプロフィール情報を取得する。lastActiveAtの単一フィールド条件で直近1か月に絞り、取得後にlastLoginAtを確認する。lastLoginAt未記録の旧ユーザーのみlastActiveAtを使い、アプリ起動時の既存heartbeatでlastLoginAtを追加する。月末を補正した日本時間での1か月前を境界にし、未来・不正な日時は対象外とする。

学習の要約は既存の同期トランザクション内で、クラウドと端末の記録をマージした後に作成する。要約未作成のユーザーだけ、batchGetのmaskで旧学習フィールドを追加取得する。旧履歴を削除・リセットしない。フィールド制限そのものは読取件数を減らさず、転送量とJSON解析負荷を減らす。旧ユーザーの要約移行前は追加読み取りが発生する。最近のユーザーに限定すること、グループ別キャッシュ、画面離脱時の中止が読取件数を減らす。RESTの429にも既存の5分バックオフを適用する。

本番のフィールド制限付きクエリは読み取りのみでHTTP 200を確認した。モックしたRESTレスポンスを使い、投影フィールド、ページ取得、古いログインの除外、キャッシュ、ロードクイズの理解度保存、取消・タイムアウト、320px/393pxでの表示をChromium・WebKitで確認する。実機iPhoneのPWAを操作した検証ではない。
