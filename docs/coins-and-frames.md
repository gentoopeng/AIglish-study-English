# コイン・フレーム・週間郵便

## 利用者向けの動作

- プロフィールで木→石→銅→銀→金→ダイヤ→プラチナ→ブラックダイヤを順番に購入する。価格は100、500、2,500、12,500、62,500、312,500、1,562,500、7,812,500コイン。購入済みの下位フレームも装備できる。
- 添付画像の透過を保った384pxのWebPフレームを使用する。アプリの静的ファイルから配信し、Firestoreに画像を保存しない。犬は追加していない。
- 郵便ポストで前日までの勉強時間（各日の分未満を切り捨て）×10＋理解度を付けた回数×1を受け取る。理解度の操作回数はこの更新以降に記録し、過去の単語数から推測しない。
- ランキングは累計と週間をボタンまたは横スワイプで切り替える。累計の理解度指標は従来の単語数、週間は理解度を付けた操作回数。
- 日本時間の月曜0時に週を終了する。終了後の起動時に前週までを集計し、勉強時間・理解度操作回数・スワイプ数の各上位3人に10,000／5,000／1,000コインの郵便を届ける。受け取りは郵便ポストで行う。

## 保存と集計

`learningActivityV1Json`は日付・操作種別・セッション別カウンターで、同じ記録の同期は最大値で統合する。既存のランキング同期トランザクションに同梱する。

`learningWalletV1Json`は既存残高を一度だけ移行した基準額、郵便別の受取額、フレーム別の支払い、装備を保存する。購入・受け取り・装備はアカウントのFirestoreトランザクションで確定する。コイン処理は理解度や勉強時間のフィールドを書き換えない。通信失敗時は購入・受け取りを確定せず、再試行できる。同じ郵便の再受取・同じフレームの再購入で残高を重複変更しない。遅れて同期された日別報酬の差額は追加受取できる。

ローカルの`core_v4_learning_wallet_v1_<ID>`と`core_v4_learning_activity_v1_<ID>`にはバックアップを持ち、古い全体セーブをロードしても現在の記録と統合する。購入済み段階と装備はプロフィールにも反映する。

終了週の結果は`learningWeeklyResultsV1/<月曜日の日付>`に一度だけ確定する。60秒の共有リースで同時集計を抑え、20ユーザーずつサーバーから取得する。複数の未集計週があってもユーザー一覧の取得は一巡にまとめる。確定済み週はその結果を再利用し、端末のキャッシュで再読込を省く。常時ポーリングやサーバーの定時ジョブは追加しない。接続・書込に失敗した週は次の起動または郵便確認で再試行する。

日別報酬の開始日は2026-10-09、週間集計の開始週は2026-10-05。更新前の理解度操作回数・スワイプ操作回数は遡って生成しない。終了後に初めて同期された未送信の学習は、既に確定した週間結果には追加しない。

## 検証

モデルの単体テストとChromium／WebKitのブラウザーテストで、購入順・旧フレーム装備・残高不足・通信失敗・二重受取・別端末の残高復元・週境界・複数アカウントの集計再利用を確認した。実Firestoreの権限・無料枠とiPhone実機での動作はこの検証に含めない。
