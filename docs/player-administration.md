# プレイヤー管理

ハンバーガーメニューの「管理者ツール」で、既存の管理者パスワードを入力します。認証前にはプレイヤー一覧を読み込みません。閉じると管理者状態を解除します。ネイティブのパスワード入力を使用し、商品管理・画像編集・装飾アニメーションは読み込みません。

- ニックネーム、登録名、年齢、対戦レートを編集できます。
- 「レートを1500に戻す」は入力値を変更します。「変更を保存」で確定します。
- 更新は対象のプロフィールとレートだけをトランザクションで変更し、サーバーの保存結果を確認します。理解度・学習時間・フレーム等は保持します。
- 管理者フォームの入力は、本人の学習データのオートセーブを起動しません。

## 完全削除

対象の名前とIDを示す確認画面で確定します。本番アカウントをテストのために削除することはありません。

最初に `users/{id}` を削除済みの最小限の印（`deleted`, `deletedAt`, `deletionState`）へ置換し、`shared/all_users` からアカウントを除外します。削除印には名前・PIN・画像・学習記録は残しません。古いIDの復活を判定するため、印そのものは保持します。

その後、対象の `vocabProgress`, `vocabBooks`, `saves`, `library`, `sync`, `libraryDeletions` とバックアップの `parts` を削除します。中断された保存で親文書がない孤立した `parts` も対象です。本人の共有メモと、本人が公開した単語帳・ワーク（従来の公開ワークを含む）を削除し、対戦部屋から本人の名前・アイコン・回答履歴・スコア・レート履歴を消去します。他の参加者の回答と結果、他人の共有メモ、他人が取り込んだ教材のコピーは保持します。

バックアップ断片は文書名の範囲で本人の配下だけを取得します。読み込みは25件ずつに区切り、文書ごとにイベントループへ制御を返します。途中で通信が失敗すると印は `pending` のまま残り、管理者画面から再実行できます。すべて完了した場合だけ `complete` にします。対象端末のローカル記録は、次のオンライン起動で削除印を確認した際に消去します。自分自身を削除した場合は、その端末の保存を消去してログイン画面へ戻します。

`account-write-guard.js` は、このバージョンのアプリによる個人データ・共有メモ・本人の対戦回答への保存を、削除印の確認と同じトランザクションで行います。既存のプロフィール読み込みは再利用します。保存を拒否しても他人への書き込みを部分的に確定しません。`shared/all_users` の古いコピーでも削除済みIDを復活させません。

このパスワードは既存のブラウザー側の管理者確認を再利用しています。Firebase AuthやFirestoreルールの変更・デプロイは行いません。変更前のコードを開いたままの端末、直接のSDK呼び出しまで禁止するには、Firebase側でも削除済みIDへの書き込みを禁止する必要があります。接続していない他端末の保存を、遠隔から直ちに消去することはできません。

## 検証

`node --test tests/*.test.cjs`、`tests/admin-players.smoke.cjs`、`tests/shared-notes.smoke.cjs`、`tests/word-duel.smoke.cjs` を実行します。ブラウザーテストはローカルのFirestore代替データを使い、本番ユーザーを変更しません。ChromiumとWebKitで、認証前の読み込み禁止、保存失敗・削除中断からの再実行、他ユーザーの記録保持、削除済みIDの保存拒否とログイン拒否を確認します。
