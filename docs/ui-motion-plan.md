# アプリ全体のアニメーション計画（App Motion）

オーナーの要望: 「あらゆる動作（ボタン、メニューを開くなど）に、おしゃれなWebサイトにあるようなCSSアニメーションを付けたい。計画を立てて、なるべく高品質に」

## 目標
- カジノ（10.106）で作った「落ち着いた大人っぽい動き」を、アプリ全体に広げる。
- 派手さより**質**: ゆっくり止まる曲線、行き過ぎ（バウンス）なし、ぼかし→くっきり、光が一度通る、時間差。
- 速い・軽い（transform / opacity / filter だけ。長い `will-change` なし）。古い端末でも引っかからない。
- 使う人が**止められる**。端末の「動きを減らす」設定を尊重し、アプリ内にも「動き」の設定を置く。
- 既存の動き（フラッシュ単語・バトル・ランキング・祝演出など）は壊さない。

## 今の状態（調査）
- 全体の動き: ボタン・入力欄・カードに共通の動きはなく、画面ごとにばらばら。タブ切り替え（`.tab-view`）は表示/非表示だけで動きなし。サイドバーは横に滑るが、暗幕は一瞬で出る。トーストは JS のインラインスタイル。
- ダイアログ: `.menu-dialog` と `.library-editor-dialog` には登場の動きあり。`app-alert`・学習方法メニュー・お知らせ等は動きなし。
- ダイアログの閉じ方: 閉じた直後に `.remove()` するコードが多い（`library.js`・`app-dialog.js`・`poker.js`ほか）。閉じる動きを入れると壊れるので、**ダイアログの「閉じる動き」は入れない**（登場の動きだけ）。
- 「動きを減らす」: 一部の CSS だけが対応。アプリ全体の切り替えは無い。
- テスト: 動きを減らす設定にしているのは 15 本、残り約 118 本は動きがある状態で走る。

## 設計の柱
1. **モード**（`<html data-motion>`）: `full`（おしゃれ・標準）／`calm`（控えめ: 時間短め・光なし）／`off`（なし）。端末の「動きを減らす」がオンなら、自動で `off`。アプリ内の設定（サイドバーの設定）で選べる。`aiglish_motion` に保存。早く（最初の描画前に）決める。
2. **新しい動きは `app-motion.css` / `app-motion.js` だけに置く**（既存のCSSは極力触らない）。`html[data-motion=full|calm]` のときだけ有効。`off` のときは、新旧どちらも止める（既存の動きも、`off` の時だけ、時間を実質0にする）。
3. **自動テスト（Playwright）では、新しい動きを既定で無効（`data-motion=test`）**にして、位置や大きさを測るテストが、動いている最中の値を拾わないようにする。動きのテストは `localStorage.aiglish_motion = "full"` を入れて有効にする。
4. **共通の値**（CSS変数）: 長さ（速い 160ms / ふつう 280ms / ゆっくり 480ms）、曲線 3種（`--am-soft`・`--am-ease`・`--am-io`）、金・シアンの光の色。`calm` は長さを0.6倍。
5. **カジノの動き（10.106）も、同じモードに従わせる**（`off`・`test` のとき止まる）。

## 段階（それぞれ別のPR。順に出して、確認しながら進める）
**第1段階: 土台と、触ったときの反応**
- モードの仕組み、変数、設定（サイドバーに「動き」）。
- ボタン全般（`.modern-btn`・ヘッダーのボタン・サイドバーの項目・ダイアログのボタン・ツールバー）: 押すと沈む、触れると光が一度通る、フォーカスのリングが静かに灯る。
- 入力欄: フォーカスで枠線に光がにじむ。カード: 触れると少し浮く。
**第2段階: 画面の行き来**
- タブ切り替え: 新しい画面が、ぼかし→くっきり＋少し上がって現れる。左右の向き（並びの前後）に合わせて、少し横から。
- 下のナビ: 選ばれた項目に、滑って移るハイライト（ピル）。アイコンが静かに持ち上がる。
- サイドバー: 暗幕がなめらかに現れて消える。項目が上から順に現れる。メニューを閉じると、静かに戻る。
**第3段階: ダイアログ・通知**
- すべてのダイアログに、共通の登場（ぼかし→くっきり＋スケール、暗幕のぼかしがなじむ）。閉じる動きは付けない（上の理由）。
- トースト: 専用のクラスにして、滑り込み＋消えるときに静かに溶ける。
- ポイント表示（ヘッダー）: 増えたとき淡く光る。
**第4段階: 中身の動き**
- リスト・カード（単語帳・ランキング・ユーザー・スタンプ）: 時間差で現れる。画面に入ってきたときに、現れる（IntersectionObserver）。
- 読み込み中の表示: 文字がゆっくり光る（シマー）。進捗バーは、なめらかに伸びる。
**第5段階: 仕上げ**
- 低い端末への配慮（動きが重いと感じたら `calm`）。細かい調整、全テスト、実機での確認。

## 守ること（品質の基準）
- すべて「動きを減らす」と「なし」で、一切動かない（テストで確認）。
- 動いている最中でも、押せる（`pointer-events` を止めない）。
- レイアウトを揺らさない（`transform` と `opacity` だけ。幅・高さ・位置は動かさない）。
- 既存のテストを変えるのは、動きが原因のときだけ。理由を記録する。
- 各段階で、動きの途中のコマを撮影して、目で確かめる。
